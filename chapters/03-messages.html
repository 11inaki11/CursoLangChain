Talking to the robot

Everything an agent knows is a list of messages. Four types, each with one job, and one twist when agents talk to each other.

state['messages']Multi-agent twist

// THE CONCEPT

An LLM has no memory and no senses. On every turn it receives the whole list of messages and continues it. Choosing the right message type tells the model who said each thing.

// YOUR ROBOT GAINS

  • A readable, debuggable history of everything it did
  • Tool results it can trust and link to its requests
  • A clean way to hear other robots

// KEY TERMS

  • SystemMessage: rules
  • HumanMessage: external input
  • AIMessage: the model's own turn
  • ToolMessage: a tool's result

Four message types

SystemMessage

The robot's rules and personality. Written by you, the developer. Usually first.

HumanMessage

Input from outside the agent: the operator's goals, questions and approvals… or another agent (see below).

AIMessage

The model's own turn: plain text, or tool_calls asking to run tools.

ToolMessage

A tool's result, linked to its request by tool_call_id.

Inspect a real history

Run the request and watch the raw objects pile up in state["messages"]. Notice how each tool_call_id links a result back to its request.

    messages = [
        SystemMessage("You are R-80, a lab robot. Be brief."),
        HumanMessage("What's your battery, and what is on the workbench?"),
    ]
    result = agent.invoke({"messages": messages})

    print("=== Raw message history ===")
    for msg in result["messages"]:
        line = f"{type(msg).__name__:<14} | {msg.text[:70]!r}"
        if getattr(msg, "tool_calls", None):
            line += f" | tool_calls={[(c['name'], c['args']) for c in msg.tool_calls]}"
        if getattr(msg, "tool_call_id", None):
            line += f" | answers={msg.tool_call_id[:8]}..."
        print(line)

The twist: when agents talk to agents

Don't read HumanMessage literally as "a human wrote this". It means "input from an external entity". When SCOUT and GRIP talk, each robot must see the conversation from its own point of view:

  • What I said → AIMessage (my own turns).
  • What any other agent said → HumanMessage (input from outside).

Same conversation, three views. Switch tabs:

Add a header saying who is talking. A HumanMessage doesn't say who sent it. Prefix it, as in [FROM: scout] …, so the robot knows whether the order came from the operator, the supervisor or a teammate. If every other agent's message were an AIMessage, the model would think it said those things itself.

def as_seen_by(agent_name: str, log: list[tuple[str, str]]) -> list:
    """Turn a shared multi-agent log into ONE agent's point of view.

    Its own lines are AIMessage; everyone else's are HumanMessage with a
    [FROM: ...] header, because for this agent they are external input.
    """
    return [
        AIMessage(text) if sender == agent_name else HumanMessage(f"[FROM: {sender}] {text}")
        for sender, text in log
    ]
